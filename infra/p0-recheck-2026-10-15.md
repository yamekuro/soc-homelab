# Bastion follow-up · public summary

Historical checks on the original bastion covered administrative access, DNS, time, selected TCP expectations, firewall login access and targeted package maintenance. A later trial with a 1 GiB guest allocation passed that basic workload; the recorded guest reading showed available memory and no swap use.

The original commands, access identities, individual connections, time peer and screenshots are kept in the private record. No synthetic transcript using illustrative addresses is published here.

These checks do not establish sustained capacity with an agent installed, every firewall rule, all phase workloads or the security state of every service. A closed TCP attempt without a matching firewall action has limited attribution. The later [MGMT evidence summary](../docs/evidence-summary.md) distinguishes the three correlated negative samples from service-only positives.

The selected [capacity plan](../docs/decisions/0009-capacity.md) and future agent workload require their own verification. A successful package-maintenance sample does not prove every package or machine was fully updated.
