# 0005 · Time synchronisation and time zone

- **Status:** Accepted
- **Date:** 2026-10-01
- **Phase:** P0

## Context

R05 makes `fw-01` the time server for every zone, so every log shares one clock. [Decision 0004](0004-upstream-dns.md) adds a constraint: DNS over TLS and DNSSEC depend on `fw-01`'s clock, so at least one NTP server must be reachable by IP address, without DNS.

Observed on 2026-10-01:

- `fw-01` ran OPNsense's default configuration: four pool names (`0.opnsense.pool.ntp.org` to `3.opnsense.pool.ntp.org`), which need DNS. After a boot at 09:07 UTC, its NTP service had no time sources until about 09:11, when the pool servers appeared. The cause of the delay was not confirmed.
- Outbound NTP works through VMware NAT and the home router, and the router does not intercept it: each server reported its own reference and stratum.
- `mgmt-01` took its time directly from `2.debian.pool.ntp.org`, Debian's default, through `fw-01` but without using `fw-01`'s NTP service. Once R13 and R15 are enforced, that traffic is blocked.
- `mgmt-01`'s time zone was `Europe/London`; `fw-01` uses UTC.
- The Windows host went to sleep after 15 minutes without input while the VMs were running. The VMs stopped; afterwards `mgmt-01`'s clock was 233 seconds behind, and `fw-01` advertised a root distance above 5 s.

## Options considered

**Time sources for `fw-01`**

| Option | For | Against |
|---|---|---|
| Pool names only (default) | No work; many independent servers | Depends on DNS, which depends on the clock; four minutes without a source after a boot |
| **Pool names plus Cloudflare by IP, with `iburst`** | Cloudflare publishes the addresses (`162.159.200.1`, `162.159.200.123`); about 22 ms from the lab; no DNS needed; with `iburst`, a server was selected about 20 s after a restart | Both IP servers belong to one operator; Cloudflare does not say whether the addresses are permanent; NTP is not authenticated |
| National time services by IP (ROA, PTB) | Official time sources | They publish host names (`hora.roa.es`, `ptbtime1.ptb.de`), not addresses |
| chrony with NTS (OPNsense plugin) | Authenticated time | A plugin and a second NTP daemon; out of scope for P0 |

**Clients**

| Option | For | Against |
|---|---|---|
| Each machine uses public servers directly | No dependency on `fw-01` | Bypasses R05; breaks when R13 and R15 are enforced; each host may follow a different source |
| **`fw-01` only, with no fallback** | One clock for every log; matches R05 | `fw-01` is a single point of failure for time, as it already is for DNS and routing |

**Time zone**

| Option | For | Against |
|---|---|---|
| Local time (`Europe/Madrid`) | Matches the clock on the Mac | An hour is repeated or skipped in the logs at every daylight saving change; harder to correlate |
| **UTC on every lab machine** | No daylight saving changes; the usual choice for log correlation | Consoles show one or two hours less than the Mac |

## Decision

- `fw-01` (ntpd, *Services ‣ Network Time ‣ General*) keeps the four default pool names and adds `162.159.200.1` and `162.159.200.123` (`time.cloudflare.com`) by IP address, with *Iburst*.
- Every lab machine takes its time only from `fw-01`, at its address in the machine's zone, with no fallback servers. On Debian, `/etc/systemd/timesyncd.conf.d/10-fw-01.conf` contains:

  ```ini
  [Time]
  NTP=10.20.10.1
  FallbackNTP=
  ```

- Every lab machine uses the `Etc/UTC` time zone.
- The Windows host does not sleep while it is plugged in (`powercfg /change standby-timeout-ac 0`).

## Consequences

- If the host sleeps or a VM is paused, the guests' clocks fall behind by the length of the pause. `fw-01`'s ntpd waits 300 s before it steps the clock, and meanwhile it adds its own offset to the root dispersion it advertises. Clients such as systemd-timesyncd, which accepts at most 5 s, then refuse its time until it recovers. Log timestamps from that window are wrong. Check `ntpq -pn` on `fw-01` and `timedatectl timesync-status` on the clients after any pause.
- If the Cloudflare addresses stop answering, `ntpq -pn` shows `reach` 0 for them. Replace them with other addresses an operator publishes.
- NTP is not authenticated. NTS through chrony is a possible improvement after P0.
- R05 must allow UDP 123 from each zone to `fw-01`, and R13 and R15 must block NTP from the zones to the Internet.
- On battery the host still sleeps after 10 minutes.
- Before restarting the host, shut down the VMs (`mgmt-01` first, then `fw-01`). At start-up, start `fw-01` first.
- To revert on `fw-01`, delete the two IP rows and save. On a Debian client, delete the drop-in file and restart `systemd-timesyncd`.
