04 / SHARED SERVICES

DNS, DHCP and time

An allow rule, a listening service and an application using it are three separate facts. Each layer has its own configuration and test.

Central DNS on the firewall

Client→Zone .1 IP:53

R05 allows TCP/UDP 53 to the firewall IP in the same zone. Unbound is enabled, listens on 53 and shows DNSSEC enabled. Manual system DNS entries were cleared and WAN DNS override was unchecked. On 20/10, UDP/TCP DNS was confirmed from the MGMT bastion, in addition to the earlier local queries.

Resolver ACLs will be assessed together with their interfaces and rules. An ACL alone does not establish WAN exposure or complete isolation.

DoT egress from the firewall itself

Unbound→upstreams TCP 853
  • Quad9: 9.9.9.10, 149.112.112.10; identity dns10.quad9.net.
  • Cloudflare: 1.1.1.1, 1.0.0.1; identity one.one.one.one.
  • Entries enabled, domain empty, Forward first and Use System Nameservers unchecked.

This traffic originates on fw-demo, separately from R05/R13a client traffic. The capture shows TCP/853 traffic to two peers; it does not by itself establish TLS authentication or the absence of fallback during a failure.

Internal names and USERS DHCP

Unbound→127.0.0.1:53053

The domains lab.example and 20.77.10.in-addr.arpa are forwarded to Dnsmasq. Its option not to forward to system DNS is checked, allowing local queries to terminate without a forwarding loop.

USERS has the only pool: 10.77.20.100–199, with a one-day lease. DNS and gateway .1 are the documented defaults; option 42 offers NTP 10.77.20.1. The offer, lease, A/PTR names and actual client use remain unverified.

Dnsmasq selects LAN/USERS, excludes LAN from DHCP and has RA unchecked. Automatic DHCP rules are not part of the 34 manual rows counted here.

DoH: address, name and browser

R13a blocks any port/protocol to IPs in the PUBLIC_DNS alias before R13. The DNSBL policy adds exact names of known services and the Firefox canary domain.

use-application-dns.net returns NXDOMAIN in the local test. This signal applies to automatic Firefox DoH; it does not replace a browser policy when the user enables DoH manually.

The lists are finite, without wildcards. There is no TLS inspection, universal resolver blocking, or testing of every DNS record type or all 15 names.

    Shared time source, observed MGMT sample

    R05 NTP allows UDP 123 to each zone firewall. An active time peer was observed; its address and sample metrics are retained in the local audit.

    The peer stratum must not be confused with the firewall stratum. On 20/10, MGMT received a stratum 2 response from the firewall and confirmed NTPSynchronized=yes after startup. Offering NTP through DHCP does not demonstrate use by the new clients; the other zones and sustained accuracy remain unverified. NTS is not implemented.

    R07: firewall logs to Wazuh

    A UDP4 destination was prepared at 10.77.50.10:514, disabled according to the owner confirmation. Local logging is retained. RFC5424 was left unchecked during preparation.

    This output originates on the firewall; it is not a duplicate LAN/SOC ingress rule. It will be enabled once the receiver is deployed, and the actual source, reception, decoding, indexing and health will be checked. UDP does not guarantee delivery.

    Aliases: values and evidence precision
    Understanding return traffic and same-segment traffic

    Return traffic in a stateful session is not a new connection initiated in the opposite direction. The order described helps explain manual rules; full evaluation also depends on existing states and earlier rules.

    Two hosts communicating directly within the same LAN Segment may not traverse fw-demo. R09 or R15 do not replace host firewalls or demonstrate isolation between those neighbours.

    Why the Tester showed rcode 0 while the real query returned NXDOMAIN

    In the 26.7.4 tag source, the Tester converts the response code twice using the same dictionary: the NXDOMAIN string becomes 3 and then 0. This explains the displayed discrepancy. Real drill queries returned NXDOMAIN. The initial interpretation of the Tester was corrected; the installed code was neither patched nor compared.

    The guide explains the discrepancy and links the technical reference. The full operational record is outside this edition; this bug does not turn the Tester into a test of client traffic.

    06 / CONTINUITY

    Validate without losing access

    The configuration is prepared for a progressive P1 deployment. Creation of the Wazuh machine and new endpoints is not yet recorded in the evidence for this review.

    Tests still pending

    1. Real USERS client. Lease, offered and used DNS/gateway/NTP, positive A/PTR, browser and DoH blocking.
    2. Traffic and logs by zone. One allowed and one blocked case per policy, with exact source/destination and a correlated rule. A timeout alone does not identify the cause. MGMT DNS and time already have a real sample; their PF rule still lacks log correlation.
    3. Full ruleset and failure cases. States, automatic/anti-lockout rules, NAT, loaded aliases, residual IPv6 and behaviour when upstreams fail.
    4. Wazuh and R07. Agents, enrolment, syslog receiver, decoding, indices and loss/recovery detection.

    Recovery and changes

    1. Retain a recovery path. A console and a verified recovery procedure must exist before administrative rules are changed.
    2. Retain separate encrypted backups. Original backups and their secret management are outside the portfolio. Their restoration still requires testing.
    3. Recover external configuration too. An application backup may not include all external settings; these must be inventoried and recovered separately.
    4. Change one specific target. Save, apply and verify the effect; retain evidence. Restoration and state capture must be checked before relying on them.
